🔬 Invariant Fuzzing
✓ 4 ✕ 2 ⏱ 1
function testFuzz_deposit(uint256 amount) public { vm.assume(amount > 0 && amount <= MAX); bank.deposit{value: amount}(); assertEq(bank.balances(user), amount); }
💥 Exploit PoC
✓ Verified
// Attack: reentrant withdraw function attack() external { bank.deposit{value: 1 ether}(); bank.withdraw(); // re-enters assertGt(address(this).balance, 1 ether); }
HIGH Reentrancy in withdraw()

The withdraw() function sends ETH before updating the balance, violating the Checks-Effects-Interactions pattern. An attacker can re-enter via a fallback function to drain funds. Detected by Slither (reentrancy-eth) and confirmed by Foundry fuzz test.

MEDIUM Integer Overflow in balance calc

Pre-Solidity 0.8 arithmetic in balance accumulation can overflow on large deposits. While SafeMath mitigates this in newer versions, legacy contracts remain vulnerable. Detected by Slither and verified with targeted fuzz inputs.

HIGH Missing Access Control

The setOwner() function lacks any modifier, allowing anyone to take ownership. Combined with reentrancy, this creates a critical attack chain. Detected by Aderyn and cross-validated by LLM with RAG knowledge from 477 audit reports.

MEDIUM Oracle Price Manipulation

Spot price from DEX reserves can be manipulated within a single transaction via flash swaps. Use TWAP oracles (Chainlink, Uniswap V3 TWAP) instead. Pattern matched from Solodit knowledge base with 0.89 similarity score.

HIGH Flash Loan Attack Vector

deposit() accepts arbitrary token amounts without verifying the caller's actual balance. A flash loan can inflate the contract's perceived TVL. Recommended: use permit + transferFrom with balance checks. Found via RAG retrieval matching EVMbench patterns.

Frequently Asked Questions

How does AuditAI differ from Slither alone?

Slither is one of our detection engines. AuditAI adds Aderyn cross-validation, LLM enrichment via RAG knowledge, automated PoC generation, and on-chain attestation. Think of it as Slither++ with verification.

What chains does AuditAI support?

AuditAI analyzes EVM-compatible Solidity code. Attestation currently targets Sepolia testnet, with mainnet support planned. Any EVM chain (Ethereum, Polygon, Arbitrum, Base, etc.) works for analysis.

Is the knowledge base available offline?

Yes. The 477 Solodit reports and 303 vulnerability references are bundled as ChromaDB vectors. First run indexes them locally; subsequent runs use the cached index.

Can I integrate AuditAI into my CI/CD pipeline?

Absolutely. AuditAI has a CLI that exits with non-zero code on findings. Use it in GitHub Actions, GitLab CI, or any pipeline. The MCP server also enables IDE integration.

Glossary

Key terms used in smart contract security.

📖
Reentrancy
When a contract calls an external contract before updating its state, allowing the external contract to re-enter the original function.
📖
Flash Loan
Uncollateralized loan that must be borrowed and repaid within a single transaction block.
📖
CEI Pattern
Checks-Effects-Interactions pattern. A coding convention to prevent reentrancy attacks.

💻 Code Examples

See AuditAI in action with real code

CLI Usage 
# Scan a single contract
$ audit-ai scan Contract.sol

# Scan with full options
$ audit-ai scan Contract.sol \
    --detector all \
    --attest \
    --output report.md

# Use knowledge base
$ audit-ai scan Contract.sol \
    --knowledge-base
Python SDK 
from audit_ai import Scanner

# Initialize scanner
scanner = Scanner(
    detectors="all",
    attest=True
)

# Scan contract
results = scanner.scan(
    "Contract.sol"
)

# Print findings
for finding in results.findings:
    print(f"[{finding.severity}] {finding.name}")
