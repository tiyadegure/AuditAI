From Detection to Proof

Forge invariant tests. Generate exploit PoCs. Verify or falsify every finding.

🔬 Invariant Fuzzing
function testFuzz_deposit(uint256 amount) public { vm.assume(amount > 0 && amount <= MAX); bank.deposit{value: amount}(); assertEq(bank.balances(user), amount); }
💥 Exploit PoC
// Attack: reentrant withdraw function attack() external { bank.deposit{value: 1 ether}(); bank.withdraw(); // re-enters assertGt(address(this).balance, 1 ether); }
HIGH Reentrancy in withdraw()

The withdraw() function sends ETH before updating the balance, violating the Checks-Effects-Interactions pattern. An attacker can re-enter via a fallback function to drain funds. Detected by Slither (reentrancy-eth) and confirmed by Foundry fuzz test.

MEDIUM Integer Overflow in balance calc

Pre-Solidity 0.8 arithmetic in balance accumulation can overflow on large deposits. While SafeMath mitigates this in newer versions, legacy contracts remain vulnerable. Detected by Slither and verified with targeted fuzz inputs.

HIGH Missing Access Control

The setOwner() function lacks any modifier, allowing anyone to take ownership. Combined with reentrancy, this creates a critical attack chain. Detected by Aderyn and cross-validated by LLM with RAG knowledge from 477 audit reports.

MEDIUM Oracle Price Manipulation

Spot price from DEX reserves can be manipulated within a single transaction via flash swaps. Use TWAP oracles (Chainlink, Uniswap V3 TWAP) instead. Pattern matched from Solodit knowledge base with 0.89 similarity score.

HIGH Flash Loan Attack Vector

deposit() accepts arbitrary token amounts without verifying the caller's actual balance. A flash loan can inflate the contract's perceived TVL. Recommended: use permit + transferFrom with balance checks. Found via RAG retrieval matching EVMbench patterns.
