从检测到证明

铸造不变量测试。生成漏洞PoC。验证或证伪每个发现。

🔬 不变量模糊测试
function testFuzz_deposit(uint256 amount) public { vm.assume(amount > 0 && amount <= MAX); bank.deposit{value: amount}(); assertEq(bank.balances(user), amount); }
💥 漏洞PoC
// 攻击：重入提款 function attack() external { bank.deposit{value: 1 ether}(); bank.withdraw(); // 重入 assertGt(address(this).balance, 1 ether); }
高危 withdraw()中的重入漏洞

withdraw()函数在更新余额之前发送ETH，违反了检查-效果-交互模式。攻击者可以通过回退函数重入以耗尽资金。由Slither（reentrancy-eth）检测并通过Foundry模糊测试确认。

中危 余额计算中的整数溢出

Solidity 0.8之前版本的余额累积算术在大额存款时可能溢出。虽然SafeMath在新版本中缓解了这个问题，但遗留合约仍然易受攻击。由Slither检测并通过定向模糊输入验证。

高危 缺少访问控制

setOwner()函数缺少任何修饰符，允许任何人获取所有权。结合重入漏洞，这会产生关键的攻击链。由Aderyn检测并通过477份审计报告的RAG知识进行LLM交叉验证。

中危 预言机价格操纵

DEX储备的现货价格可以在单个交易中通过闪电交换进行操纵。建议使用TWAP预言机（Chainlink、Uniswap V3 TWAP）。从Solodit知识库中以0.89相似度分数匹配的模式。

高危 闪电贷攻击向量

deposit()接受任意代币数量而不验证调用者的实际余额。闪电贷可以膨胀合约的感知TVL。建议：使用permit + transferFrom并进行余额检查。通过匹配EVMbench模式的RAG检索发现。
